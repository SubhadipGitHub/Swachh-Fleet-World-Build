# Data sources and provenance

> Status: **Stage 1 research log, updated in Stage 2 (2026-10-14).** Each figure is tagged with how it may be used.
> Stage 2 verified the ward cluster, ward populations, the KCDC location and the OSM coverage (§1, §1a, §1b).
> Figures still marked *to verify* are confirmed or replaced during the M1 data extraction, before any code
> depends on them. Every `sourceId` in the app's config must match an entry here (architecture AD-9).

## Provenance tags

| Tag | Meaning | Shown in the app as |
|---|---|---|
| `real` | Taken directly from a published dataset or official figure (e.g. an OSM road, a published tonnage). | "Real · <source>" |
| `derived` | Calculated from real figures (e.g. waste per ward = population × per-capita rate). | "Derived from <sources>" |
| `assumed` | A reasoned default where no public figure exists (e.g. auto-tipper fuel economy). Configurable. | "Assumed" |
| `synthetic` | Generated by the seeded simulation (e.g. a bin's live fill reading, a vehicle ID). | "Simulated" |

The wards are contiguous: Koramangala W/E → Jakkasandra → HSR Layout → Agara / Mangammana Palya → Hosapalya.
Ward numbers repeat across corporations, so the app always shows them as "South-72 HSR Layout". Populations are
the 2011 Census figures the delimitation was built on (the delimitation states this), so they are `real` but
dated 2011. The 2026 figure is a projection (`assumed` growth factor, requirements W-5).

### 1b. OSM coverage sample (fetched 2026-10-14)

A bounding box around the cluster (12.893–12.945 N, 77.608–77.660 E, ~32 km², which is wider than the 7 wards) holds:

| Feature | Count | Implication |
|---|---|---|
| Building footprints (ways) | 38,941 | ≈1,200 per km², so about 14,000–16,000 inside the cluster. The fetch script reports the exact count |
| …with `building:levels` | 662 (1.7%) | Heights are almost all `assumed` (by building type and area) |
| …with `height` | 18 | |
| Drivable roads (motorway…living_street incl. service) | 6,262 ways | Road graph of roughly 15–20k directed edges after splitting at junctions |
| …tagged `oneway=yes` | 771 | One-way rules respected in routing |

The public Overpass servers often time out on area queries. The fetch script uses bounding-box queries, retries
with backoff, and falls back to mirrors (architecture AD-3).

## 5. Smart-bin and routing evidence (for scenario defaults)

| Claim | Source | Tag | Notes |
|---|---|---|---|
| ~20% fewer collection trucks needed with fill sensing plus route optimisation | Mumbai (Malad) academic study, IIETA journal, 2025 | `assumed` reference point | The authors' estimate; no fuel-litre data published |

The app does **not** hard-code a savings figure. Savings come out of the simulation, and the ~20% study is shown
only as an external reference next to the result.

## 6. Not publicly available (will be `synthetic`)

- Live bin fill-level sensor readings.
- Live vehicle GPS tracks, fuel logs and driver attendance.
- Per-street household waste generation.

These are generated by the seeded simulation and calibrated to the figures above. A later milestone adds import of
real JSON/CSV feeds (requirements §9) so a city team could replace them.

## Assumptions log (`kasaflow-assumptions`)

Each `assumed` figure in the config has a note. The main ones:

| Figure | Default | Why |
|---|---|---|
| Growth factor 2011 → 2026 | 1.6 | Placeholder for Bengaluru's growth since the 2011 Census; *to source in M1* |
| City population 2026 | 14,000,000 | Placeholder used for per-capita waste and black-spot scaling; *to source in M1* |
| Persons per household | 3.9 | Typical urban Karnataka household size; *to source in M1* |
| Compactor payload | 6 t | Typical urban compactor load |
| Compactor trips per day | 3 | Typical for a ~10 km haul to KCDC |
| Waste composition | 60% wet, 30% dry, 10% reject | Typical Indian urban MSW split |
| Transfer points | 5 | No public list found for the cluster |
| Smart bins | 120 | Scenario lever (markets, commercial streets, transfer points, black spots) |
| Free-flow reference speed | 30 km/h | Uncongested urban arterial speed the TomTom averages are compared with |
| Free speed and lanes by road class | `src/routing/graph.ts` | Used where OSM lacks `maxspeed` or `lanes` |
| Daily generation profiles | household morning peak; market evening peak | Shape only; the daily totals come from the per-capita rate |
